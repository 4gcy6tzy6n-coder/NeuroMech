# M5 recurrent-reservoir bandit — strengths and failure lessons

## What worked

- The eligibility trace retained a positive average advantage over a current-score/no-trace update after policy features were generated by a recurrent state: +0.002887 held-out expected reward, paired task-seed bootstrap 95% interval [+0.002089, +0.003815].
- Shared task, context, action-choice uniforms, and potential reward uniforms enabled paired comparisons across arms and delays. The task seed, rather than individual decisions, was the inferential unit.
- The result extends the limited synthetic evidence from feed-forward to a recurrent feature generator without changing the task or retuning the update parameters.

## Failures and boundaries

- The mean advantage was modest, only 27/30 seed averages were positive, and it decreased from +0.003982 at delay 1 to +0.001423 at delay 64.
- Exact replay remained clearly stronger (0.51812 versus 0.50327 for trace), so the trace is not an efficient substitute for exact credit assignment in this setting.
- The recurrent core was fixed random reservoir dynamics; only its linear readout learned. This does not demonstrate learning recurrent weights or transfer to a trained RNN/LNN/LTC.
- Runtime emitted NumPy matrix-operation warnings. Outputs were all finite and the estimand/interval independently recomputed, but the warning source was not isolated. Record this as a code/runtime diagnostic issue rather than silently discounting the warning.
- This post-result single-objective synthetic test is not biological validation, connectome transfer, or broad AI superiority.

## Next improvement

Diagnose the numerical warning with a separately versioned implementation before any follow-up; then, if extending M5, test actual recurrent-core learning under a new preregistered exploratory contract and report exact replay as the stronger reference. Do not tune this completed run in place.
